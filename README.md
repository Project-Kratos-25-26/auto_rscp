# ARC Rover - RSCP Implementation Guide

## 1. What is RSCP?

The **Rover Satellite Communications Protocol (RSCP)** is the official messaging standard for ARC. Since rovers are not allowed to use their own antennas, they must interface with a provided **Client Module (RSC-CM)** via an **RS-232** serial connection at **115200 bps**.

RSCP handles two types of data:

* **RequestEnvelope**: Commands sent from ARC officials to the rover (e.g., `SetStage`, `MapsToGPS`).
* **ResponseEnvelope**: Data sent from the rover back to officials (e.g., `Acknowledge`, `TaskFinished`, `RoverStatus`).

---

## 2. Project Directory Structure

Here are the current files in your `~/Downloads/rscp_protobuf` directory and their functions:

* **`rscp.proto`**: The "source of truth." It defines the structure of all messages (GPS, battery, stages).
* **`rscp_pb2.py`**: The Python code generated by the Protobuf compiler. **Do not edit this file manually**.
* **`rscp_bridge.py`**: The transport layer. It handles **COBS framing** (adding `0x00` delimiters) so that the serial stream can be parsed correctly by both ends.
* **`rover.py`**: The rover's main firmware logic. It is non-blocking, meaning it can "drive" to a target while simultaneously broadcasting 1Hz telemetry.
* **`emulator.py`**: A simulator that acts as the ARC Official. It sends commands and unwraps every parameter of the rover's response for debugging.

## 3. Installation & Setup

To run the emulation, you must install the following dependencies:

```bash
# 1. Standard Python libraries
pip install pyserial cobs protobuf

# 2. Virtual Serial Port tool (Linux only)
sudo apt-get install socat

```

## 4. How to Emulate a Mission

To simulate the connection between the RSC-CM and the Rover, follow these steps in three separate terminals:

### Step 1: Create the "Virtual Cable" (Terminal A)

This command links two virtual ports. Anything sent to `/dev/pts/1` will appear on `/dev/pts/2`.

```bash
socat -d -d pty,raw,echo=0 pty,raw,echo=0

```

*Note the output paths provided by socat.*

### Step 2: Start the Rover (Terminal B)

The rover will start broadcasting its status every second.

```bash
python3 rover.py --port /dev/pts/1

```

### Step 3: Start the Official Emulator (Terminal C)

The emulator will send a navigation command and wait for the rover to finish.

```bash
python3 emulator.py --port /dev/pts/2

```

## 5. Protocol Rules for Developers

When adding new features, you must follow these ARC constraints:

* **Acknowledge**: You must send an `Acknowledge` message immediately after receiving any command from officials.
* **Telemetry Rate**: Full `RoverStatus` updates must not exceed **1Hz**.
* **Battery Charge**: Always send the `state_of_charge` as a float between **0.0 and 1.0** (e.g., 0.85 for 85%).
* **Coordinates**: Use **double-precision** for latitude and longitude to ensure accuracy under the **EGM96 model**.
